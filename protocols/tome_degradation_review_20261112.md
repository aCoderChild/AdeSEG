## What the evidence does and does not show

1. **The change begins when compression begins.** Saved prediction and memory hashes match native through six history maps. This localizes the effect to the compressed long-history path, but does not identify one cause.
2. **Region matching is not the main fix.** On the completed 12-map cohort, regional minus generic is only +0.000344 Dice (95% CI [−0.000389, +0.001271], Holm p=0.273). In the active interim, regional and generic arms are also nearly identical.
3. **Token allocation is not enough.** Recent-dense allocation changes seq6 by less than 0.001 Dice relative to uniform and remains about 0.04 below native.
4. **The cohort regressions are method behavior; a separate gate setup bug was found.** The saved full-run audits pass frame alignment, layer coverage, mass/pointer accounting, frozen weights and pre-compression parity. The new representative-position engineering gate initially failed because it used one CPU thread and deterministic-kernel dispatch, while its archived native reference used two threads and default dispatch. This changed SAM2's BF16 memory features even though predicted logits were identical. Under the baseline-matched two-thread runtime, fresh native and candidate runs match masks and stored memory exactly. This is a gate-runtime correction, not a correction to full-run ToMe results.
5. **Likely risks remain confounded:** averaging already RoPE-rotated keys mixes spatial phases; mass correction is exact only for identical keys/values; histories older than six maps reuse the oldest learned temporal slot by design; and additional old masks can carry stale object evidence. The temporal-slot extension was checked against SAM2's `num_maskmem - t_pos - 1` lookup and preserves ages 1–6 correctly. The existing experiments change several factors together, so none is proven as the sole cause.

## Isolated implementation candidate

Added `modeling/position_consistent_history_tome.py`. It reuses the existing `PositionConsistentRegionToMe` integration and pinned author ToMe operations. It applies exact per-frame/window quotas and merges memory content before SAM2's K/V projection and RoPE. For each merged cluster, it keeps the destination token's original SAM2 position embedding and applies RoPE at that same representative grid coordinate. The representative position remains from the same source frame, so its temporal slot is retained. Frames are never mixed; pointers remain unchanged; SAM2 weights remain frozen.

This candidate tests one plausible correction: avoid merging already-RoPE-rotated keys and avoid averaging the SAM2 position embedding across different token coordinates. It deliberately keeps the existing temporal-slot extension, so it does **not** solve age aliasing or stale-memory leakage and is not claimed to improve Dice. It uses generic matching to isolate position handling; regional matching has not shown a cohort-level benefit. Weighted content merging and log-mass correction remain approximations when the source keys/values differ.

## New targeted candidate: joint key/value matching

The seq6 errors have two directions: some compressed predictions spill beyond the polyp, while others miss foreground. This makes a single size-based explanation inadequate. The present matching metric is based on K similarity alone. Because SAM2 attention scores queries against K but returns the matched content from V, similar K does not guarantee similar segmentation content in V.

I added an optional `key_value` matching metric to the already implemented position-consistent ToMe path. It builds equal-scale, separately normalized descriptors from each layer's frozen, head-averaged K and V projections before RoPE, then passes their concatenation to the pinned official ToMe matcher. The match is still within a source frame and local 4x4 window; the memory merge, spatial representative, mass correction, history schedule and token budget are unchanged. The default remains key-only, preserving prior behavior. This is a plausible mechanism-level correction, not a promised Dice gain.

The pinned official ToMe operation was also checked on a synthetic two-token counterexample, with both tokens assigned the same region. For keys `[1,-0.5]`, `[1,0.5]`, values `0`, `1`, and query `[0,4]` (unit attention scale), native attention returns 0.982014; merged attention with the correct log-mass bias returns 0.5. With zero query both return 0.5. Thus the exact cluster contribution depends on the query: `logsumexp(q·k_i)` generally differs from `q·mean(k_i)+log(n)`, and value averaging removes query-dependent within-cluster preferences. Regional identity cannot by itself guarantee that averaging is safe. This is a mathematical applicability check, not evidence that the same example caused seq6 errors. Script and result are beside the correction receipt as `merge_counterexample.py` and `.json`.

### Correction to the proposed K/V decomposition

A synthetic check using pinned official ToMe matching, weighted merging and unmerging established an important coupling. If each averaged key is expanded to every original member position, then all members have identical attention scores. Their original values are therefore averaged implicitly by attention. Consequently `attention(Q, expanded_mean_K, original_V)` equals `attention(Q, merged_K, merged_V, log_mass)` for the fixed partition with unit source masses. A separate value-only counterfactual is meaningful, but its error and the key-only error are not independent additive contributions. This identity also holds with untouched pointers. Do not interpret a naive K-only/joint difference as evidence that V is irrelevant.

Two fresh processes reproduced the check exactly. No-removal outputs are exact; the compressed fixture's K-only and joint outputs agree within 2.22e-16 in float64, with input and pointer preservation. These are synthetic engineering results, not PolypGen findings. Scripts, fixture hashes and replay receipt are at the same Drive correction folder (`fixed_assignment_decomposition.py`, `.json`, `fixed_assignment_replay_receipt.json`). The next real-read diagnostic must report joint effects and interactions, query-dependent cluster score spread and within-cluster value variation; it must not claim to identify two independent causal effects from this decomposition.
